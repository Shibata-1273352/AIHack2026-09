## 比較から分かること

- AIが判断する方式のなかでは、最安が **B 製品のルーティング（既定）**（平均 $0.001134/件）、最速が **B' 自前フォールバック**（平均 79.5秒）。**最安と最速が別の方式になった**
- R（固定ランブック）は当然いちばん安く速い（$0.000174 / 39.2秒）が、**想定済みの障害しか扱えない**。同じ土俵の比較ではない
- A（高性能モデル固定）の費用は B の **73.5倍**。しかも所要時間は **0.99倍**でほぼ同じだった。判断回数も平均 5.0 対 6.5 呼出と大差なく、**高性能モデルの手数の少なさは単価差をまったく埋め合わせなかった**
- 同じ「安いモデルを使う」でも差が出た。製品のルーティング（B）は自前フォールバック（B'）の **0.24倍**（= 約 4.1分の1）の費用で済み、代わりに B' のほうが **1.7倍速い**。**安さを取るか速さを取るかの選択になる**
- B が使ったルータ: `fusion-flash`。**試行ごとに解決先モデルが変わっている**（実際に使われたモデル: `gpt-5.6-luna`, `openai/gpt-oss-120b`, `qwen/qwen3.7-flash`）。モデルを1つに固定していないことが、そのまま記録に残る
- 条件 C-0 正常時（障害なし）: 全 8 試行で正常時に**不要な変更を提案しなかった**
- 条件 C-1 主回線断のみ（冗長化制御で業務は正常）: 全 8 試行で冗長化制御で業務が戻っている状況で、**変更せず残存課題として引き継いだ**

## 読み方

- **費用は推定ではなく実請求額**。OrcaRouter の `GET /v1/generation` が返す
  `total_cost`（USD・確定額）を呼出ごとに引いて合算している。実費が取れなかった
  呼出だけ単価表からの推定で補い、その件数を `cost_unpriced_calls` に記録する
- **成功1件あたり費用**（§12.2）は、失敗試行で発生した費用も分子に含めた実効コスト
- 合否の基準は条件ごとに違う。T-04 は「原因を特定し承認された1件だけを適用して復旧」、
  C-0 は「**不要な変更を提案しない**」、C-1 は「変更せず残存課題として引き継ぐ」
- R方式の費用は構成図読取1回分のみ。判断にLLMを使わないぶん安価だが、
  **想定済みの障害しか扱えない**（観測順・判断が決定木に固定されている）。
  A/B は観測結果に応じて次の手を組み立てるため、未知の障害にも手順を伸ばせる
