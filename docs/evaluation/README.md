## 結果を読む前提

方式比較の記録は、複合障害・正常時・主回線断のみの3条件について、4方式を各2回実行したものです。
条件ごとに合格の意味が異なります。複合障害では復旧、正常時では不要な変更を提案しないこと、主回線断のみでは変更せず残存課題を引き継ぐことを確認しています。

承認は評価スクリプトによる自動代行です。人が内容を理解して判断する時間を測ったものではありません。
固定手順方式も構成図の読取にはAIを使っており、AI費用がゼロの比較対象ではありません。

費用は請求情報を取得できた呼出と、取得できず推定で補った呼出を区別して読む必要があります。
詳細と`cost_unpriced_calls`の扱いは[実測結果](results.md)を参照してください。
呼出前の予算判定と、呼出後の費用表示の設計は[アーキテクチャ](../architecture.md)にあります。

これらは記載条件での結果です。少数試行から一般的な性能差や未知の障害への対応を保証するものではなく、要件定義の54試行計画の完了を意味しません。

## 機能ごとの証拠

| 対象 | 証拠の種類 | 参照先 |
| --- | --- | --- |
| 複合障害の復旧・正常時の無変更・主回線断の引き継ぎ | 実測ログ | [方式比較](results.md) |
| 未承認・ハッシュ不一致・期限切れ・二重承認の拒否 | 自動テスト | [test_approval.py](../../backend/test_approval.py) |

| 処理中リセット・注入と旧案件への承認の拒否 | 自動テスト | [test_demo_reset.py](../../backend/test_demo_reset.py) |
| 未検証モデル・処理中・無認証の切替拒否 | 自動テスト | [test_model_select.py](../../backend/test_model_select.py) |
| 却下・受領・保留・再調査の引き継ぎ | 自動テスト | [test_handoff.py](../../backend/test_handoff.py) |
| 禁止ルール削除・無認証操作・命令埋め込みへの対応 | 実測ログ | [攻撃検証](../evidence/T-11.md) |

自動テストの実行方法は[開発ガイド](../development/README.md)にあります。
自動化されていない確認は、テストと同等の再現性を持つものとして扱いません。

## 比較を再実行する

シミュレータを起動し、OrcaRouterのAPIキーを設定した上で、リポジトリ直下から実行します。
実行中はシミュレータをリセット・変更し、自動代行承認を行います。通常のデモと同時に実行しないでください。
実呼出に利用料が発生し、評価用の出力ファイルが更新されるため、保存済み結果を残す場合は実行前に退避してください。

```bash
cd backend
uv run python scripts/eval_abr.py --trials 2 --conditions T04,C0,C1
uv run python scripts/bench_models.py
```

未実装・未検証の残項目は[制約と確認状況](../limitations.md)を参照してください。
