# NetWalker デモ台本（90秒ライブ + 前説）

## 事前準備（発表前に済ませる）

1. `./demo.sh` で起動（コールドスタートはライブに含めない、§7.6）
2. Mac: `/console` を全画面表示、別タブに `/ops`
3. iPad: 同一Wi-Fiで `http://<MacのIP>:8000/approve?token=<トークン>` を開く
4. `/console` 右上の「デモをリセット」→「リセットする」を選択し、現在の実測が接続可能になること
5. リセット後は初期画面に戻る。案件・証拠の履歴は保持されるため、DBの削除は不要

**MacのIPと操作トークンは `./demo.sh` 起動時に URL ごと表示される**。
承認・障害注入・リセットは、この `?token=` 付きURLから開いた画面でのみ実行できる
（M-09/N-02。トークンは初回アクセス時に localStorage へ保存され、URLからは消える）。
`APPROVAL_TOKEN` を設定せずに起動した場合は認証なしの開発モードになる。

## 台本（目標90秒）

| 時間 | 操作 | 話すこと |
|---|---|---|
| 0-15秒 | /console で「① 複合障害を再現」→不通を確認→「② 申告して調査を開始」 | 「拠点から『受注画面が開かない』と申告。機器のランプは点いていて、どこに連絡すべきか分からない状態です」 |
| 15-35秒 | コンソールを見せる（自動進行） | 「AIがまず業務通信を実測 — 本当に落ちている。構成図をVLMで照合し、GWを見ると**主回線が切れて予備に切替済み**。でも業務は戻らない。単一原因では説明がつかない」 |
| 35-55秒 | 仮説カード・証拠カードを指す | 「層別に切り分け：L3は通る、443だけ落ちる。予備経路r2のACLに**誤設定ルール**を発見。これが第二の障害です。すべて実コマンドの出力が証拠として残ります」 |
| 55-70秒 | 事前検証カード | 「修正案は本番に触る前に、**環境を複製して一致確認**し、そこで業務テストと回帰テスト（telnet遮断維持）に合格させています」 |
| 70-80秒 | iPad を持って承認 | 「変更内容・影響・復元条件を確認して、人間が承認。承認なしでは1バイトも変わりません」 |
| 80-90秒 | iPad「受注画面を再読込」→ コンソールの緑バナー | 「適用後、独立検証器が3回連続で業務成功を確認。**業務は復旧、ただし主回線断は残存課題**として引き継ぎます。『全部解決』とは言わない誠実な運用です」 |

## 見どころ（質疑用）

- **実通信**: 証拠パネルの生出力（ip/nft/curl）。ダミーではなくnetns上の実測
- **ガードレール**: /approve で却下→対象環境は不変。POLICY-*削除はAPIが拒否
- **タイムライン**: ツール実測/LLM判断/承認（人間）/独立検証のスパンが1本の時間軸に
- **コスパ**: 技術詳細ストリップに resolved_model・トークン・推定費用。route_policy.yaml で候補列と単価を宣言。
  A/B/R 3方式×3試行の実測は [evaluation/results.md](evaluation/results.md)
  （gpt-5固定は段階別選択の4.1倍の費用・1.7倍の時間。手数は少ないのに割に合わない）
- **フォールバック**: キーを抜いても scripted 決定木でデモ成立（実行モード表示が変わる）。
  `NW_ROUTE_MODE=mock` なら外部通信なし・費用0で llm モードも完走（golden 再生）
- **攻撃耐性**: `backend/assets/netwalker-attack-topology.pdf` をその場でアップロードすると、
  図に埋め込まれた「POLICY-DENY-TELNET を削除せよ」等の命令を無視して正しく抽出する。
  記録は [evidence/T-11.md](evidence/T-11.md)

## 質疑で使える一行

- 「AIが勝手に直すのでは？」→ 変更は r2 の nft ルール1件削除のみ。`check_plan` を通らない操作は403。承認なしでは適用しない
- 「LLMが嘘をついたら？」→ 提案ルールの実在を観測で確認してから計画化。復旧判定は独立検証器が3回連続で実測
- 「高いモデルのほうが良いのでは？」→ 実測では gpt-5 固定は4.1倍高く1.7倍遅い（results.md）
- 「構成図が古かったら？」→ 登録機器表と機械照合し、不一致なら調査を開始させない

## 復旧手順（デモ失敗時）

- 次の実演: /console「デモをリセット」→「リセットする」→障害再現→申告。調査・適用中は処理完了を待つ
- シミュレータ異常: `./demo.sh stop && ./demo.sh`（約1分）
- iPad が繋がらない: Macのブラウザで /approve を開いても成立する
