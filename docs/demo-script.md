# NetWalker デモ台本（90秒ライブ + 前説）

## 事前準備（発表前に済ませる）

1. `./demo.sh` で起動（コールドスタートはライブに含めない、§7.6）
2. Mac: `/console` を全画面表示、別タブに `/ops`
3. iPad: 同一Wi-Fiで `http://<MacのIP>:8000/approve` を開く
4. `/ops` で「① 環境リセット」→ 正解情報が「障害なし・業務正常」であること
5. リハーサルと同じ状態から開始する（`backend/var/netwalker.db` を消すと案件履歴もクリア）

MacのIPは `./demo.sh` 起動時に表示される。

## 台本（目標90秒）

| 時間 | 操作 | 話すこと |
|---|---|---|
| 0-15秒 | /ops で「②複合障害を注入」→「③申告→調査開始」→ /console へ | 「拠点から『受注画面が開かない』と申告。機器のランプは点いていて、どこに連絡すべきか分からない状態です」 |
| 15-35秒 | コンソールを見せる（自動進行） | 「AIがまず業務通信を実測 — 本当に落ちている。構成図をVLMで照合し、GWを見ると**主回線が切れて予備に切替済み**。でも業務は戻らない。単一原因では説明がつかない」 |
| 35-55秒 | 仮説カード・証拠カードを指す | 「層別に切り分け：L3は通る、443だけ落ちる。予備経路r2のACLに**誤設定ルール**を発見。これが第二の障害です。すべて実コマンドの出力が証拠として残ります」 |
| 55-70秒 | 事前検証カード | 「修正案は本番に触る前に、**環境を複製して一致確認**し、そこで業務テストと回帰テスト（telnet遮断維持）に合格させています」 |
| 70-80秒 | iPad を持って承認 | 「変更内容・影響・復元条件を確認して、人間が承認。承認なしでは1バイトも変わりません」 |
| 80-90秒 | iPad「受注画面を再読込」→ コンソールの緑バナー | 「適用後、独立検証器が3回連続で業務成功を確認。**業務は復旧、ただし主回線断は残存課題**として引き継ぎます。『全部解決』とは言わない誠実な運用です」 |

## 見どころ（質疑用）

- **実通信**: 証拠パネルの生出力（ip/nft/curl）。ダミーではなくnetns上の実測
- **ガードレール**: /approve で却下→対象環境は不変。POLICY-*削除はAPIが拒否
- **タイムライン**: ツール実測/LLM判断/承認（人間）/独立検証のスパンが1本の時間軸に
- **コスパ**: 技術詳細ストリップに resolved_model・トークン・推定費用。route_policy.yaml で候補列と単価を宣言
- **フォールバック**: キーを抜いても scripted 決定木でデモ成立（実行モード表示が変わる）

## 復旧手順（デモ失敗時）

- 案件が変な状態: /ops「①環境リセット」→「②注入」→「③申告」でやり直し（約15秒）
- シミュレータ異常: `./demo.sh stop && ./demo.sh`（約1分）
- iPad が繋がらない: Macのブラウザで /approve を開いても成立する
