# NetWalker

**たらい回しを、ここで終わらせる。**

構成図を読み、実測から次の調査を選び、人の承認を経て業務再開まで確かめるAIエージェントです。
調査の証拠と残る課題を一つの案件にまとめ、担当が変わっても対応を引き継げます。

## 解決したい課題

「業務画面が開かない」。社内IT、回線窓口、機器保守へ問い合わせるたび、同じ説明を繰り返す。
それぞれが担当範囲を調べても、原因が複数重なっていると、業務が戻らないことがあります。

現場が必要としているのは、調査結果の断片だけでなく「どうすれば仕事を再開できるか」です。
NetWalkerは、構成図・実測結果・変更の判断・復旧確認をつなぎ、調査と引き継ぎの分断を減らすために開発しました。

## 開発したもの

ネットワーク障害の申告から、調査・修正案の検証・承認・業務復旧確認までを扱うWebアプリです。
Macのコンソールで調査を追い、iPadから変更を承認できます。

| AIが調べる | 人が承認する | 復旧まで確かめる |
| --- | --- | --- |
| 構成図PDFから機器と接続を読み取り、登録情報と照合。通信や機器の状態を実測し、結果に応じて次の調査を選びます。 | 対象環境を複製し、修正案を先に検証。変更する差分と検証結果を見て、人が承認します。 | 承認された変更を適用し、業務通信の回復と禁止通信の遮断を確認。残る課題は証拠とともに引き継ぎます。 |

調査の進行、原因の仮説、変更内容、AIの利用モデルと費用を同じ案件から確認できます。
判断できない場合や変更を却下した場合には、人への引き継ぎに進みます。

## 今回のデモで見せること

題材は、拠点の「受注画面が開かない」という申告です。
**主回線の停止**と**予備経路の通信ルールの誤設定**が重なり、回線が自動で切り替わっても業務が戻らない状況を再現します。

1. ネットワーク構成図を読み込み、機器と接続を確認する。
2. 実測を重ね、主回線と予備経路それぞれの問題を調べる。
3. 複製した環境で、修正後に業務通信が通り、禁止通信は遮断されることを確かめる。
4. 人が変更内容を承認し、許可された通信ルールの変更を適用する。
5. 業務の再開を確認し、主回線の停止は残存課題として引き継ぐ。

デモには、5台の機器と主・予備経路を持つLinuxの模擬ネットワークを使っています。
実際にHTTPS通信を流すため、障害と修正の効果を通信結果で確認できます。
画面の「デモをリセット」で、繰り返し実演できます。

→ [起動してデモを試す](docs/getting-started/README.md) / [発表用のデモ台本](docs/demo-script.md)

## 実装と検証の範囲

AIHACK2026の提出作品として、構成図の読取、実測に基づく調査、変更前の検証、人の承認、復旧確認と引き継ぎを実装しています。
OrcaRouter経由のモデル比較と、承認・送信制限・不正入力に関する検証記録も公開しています。

今回の対象は、模擬ネットワーク上の限定した障害シナリオです。任意の実機ネットワークへの対応や、あらゆる障害からの自動復旧を保証するものではありません。
未実装・未検証の項目は[制約と確認状況](docs/limitations.md)にまとめています。
